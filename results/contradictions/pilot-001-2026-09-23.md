## Isolate
T3 computes `math.fsum(math.sin(i) for i in range(1000))` (suite.py line 63).
`math.fsum` is exactly specified, so the delta is inherited from `math.sin`,
which dispatches to the platform C libm: glibc on Track M (Linux) vs the
Windows CRT on Track C (win32). Transcendental libm functions are not
bit-identical across implementations; per-term 1-ULP differences over 1000
terms accumulate to the observed 5.55e-16. This is a real platform difference
in the sensor (the float computation), not an executor error: both tracks ran
the identical procedure (procedure_hash a5077f2f... verified on both).

## Classify
- Primary: DETECTOR-SPEC. The cross-track comparator (`diff_tracks`) demands
  exact canonical-JSON equality, while the clause itself declares tolerance
  1e-9 for this field. Per the clause's own semantics the tracks agree:
  |M - C| = 5.55e-16 << 1e-9. The detector is stricter than the spec it serves.
- Secondary: PREMISE. The tacit premise "identical procedure yields
  bit-identical floats on every platform" is false when libm transcendental
  functions are involved. The clause anticipated this with tolerances; the
  detector did not honor them.
- Ruled out: PROCEDURE (hashes match both tracks), MODEL (no model judgment
  involved in execution), SENSOR-as-fault (both readings valid per spec),
  RIG-as-fault (rig difference is real but within the clause's tolerance band).
